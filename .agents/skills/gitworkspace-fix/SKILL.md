# GitWorkspace 问题修复流程

本 skill 教你在 **GitWorkspace** 项目中，如何基于 `docs/tasks-fix/` 的任务文档**开始修复**或**继续修复**某个用户反馈的问题（F-XX 编号）。

## 文档地图

用户反馈的问题已拆解在 `docs/tasks-fix/` 下：

| 文件 | 作用 | 何时读 |
|---|---|---|
| `docs/tasks-fix/README.md` | 总索引：全部 F-XX 问题的优先级/状态总表 + 维护规范 | 选问题、核对状态时 |
| `docs/tasks-fix/F-XX-*.md` | 问题 spec：问题描述 / 定位线索 / 修复范围 checklist / 验收标准 / 进度 | 修复目标问题时 |

约束文档（按需加载，不重复读）：

- Git 功能相关 → `docs/tasks/00-全局开发约束.md`
- Runtime（R-XX）相关 → `docs/tasks-runtime/00-全局开发约束.md`
- 涉及路径 / 进程 / 可执行文件检测 → 根目录 `AGENTS.md` 的「平台兼容性开发规范」

## 开始修复一个问题

1. 确定问题编号（用户指定，或从 README 总表选一个 ⬜ 的；💬 讨论项不进入修复流程）。
2. 读目标任务文档，明确：问题描述、定位线索、修复范围 checklist、验收标准。
3. 按任务文档的关联任务/定位线索，加载对应约束文档与源码位置——**只读相关的，不要全读**。
4. 把任务状态 `⬜ → 🟦`（**同步**更新 README 总表 + 任务文档「进度」章节），并在时间线追加一行「开始修复」。
5. 先复现问题（按「问题描述」的复现案例），确认现象后再动手；能写失败测试的先写失败测试。
6. 实施修复。

## 继续修复（恢复一个进行中的问题）

1. 读目标任务文档「**进度**」章节：当前状态 + 时间线最后一条 + 子任务清单勾选情况。
2. 读 `README.md` 总表该行，核对两处状态一致（不一致时以任务文档为准，并修正 README）。
3. 从时间线最后一条记录恢复上下文，继续**未勾选的子任务**。

## 完成一个修复

1. 逐条核对「验收标准」，**全部满足**才算完成；有复现案例的必须用原案例实测验证。
2. 运行相关验证（`cargo test` / `cargo check` / `pnpm build` / `vue-tsc`，按改动范围选择）。
3. 更新任务文档「进度」：状态 `→ ✅`，时间线追加一行（日期 + 根因 + 修法 + 验证命令）。
4. 同步更新 README 总表该任务状态 `→ ✅`。
5. 若修复牵出独立新问题，提示用户新增 F-XX 文档，不要在原任务里扩张范围。

## 必须遵守

- **两处同步**：状态与进度必须同时更新 README 总表和任务文档，规则以 `docs/tasks-fix/README.md` 末尾「维护规范」为准。
- **最小修复**：只修文档「修复范围」内的问题，不顺手重构无关代码。
- **平台规范**：涉及 Windows/macOS/Linux 差异的修复，先对照根目录 `AGENTS.md` 平台规范（路径归一化、PATHEXT、`CREATE_NO_WINDOW` 等）。
- **代码落点**：Rust 后端在 `src-tauri/src/`，Vue 前端在 `src/`（api / components / composables / stores / views）。
