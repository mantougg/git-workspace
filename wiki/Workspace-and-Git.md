# 工作区与 Git 操作

GitWorkspace 的核心单位是**工作区**：一个包含多个嵌套 Git 仓库的根目录。项目根目录本身可以不是 Git 仓库。

## 工作区管理

- **添加工作区**：在「工作区管理」页以目录为单位添加，支持自定义扫描深度；
- **自动发现**：递归扫描自动跳过 `node_modules`、`target`、`dist`、`build`、`.next`、`venv` 等目录（100 个仓库首次扫描 < 2 秒）；
- **分组浏览**：仓库按层级分组展示，可筛选、收藏、打标签；
- **Dashboard 与健康检查**：整个工作区总览，自动检测异常（detached HEAD、LFS/Submodule 异常、陈旧分支等）;
- **工作区 Manifest**：把仓库清单导出为 JSON，换台机器可一键批量 Clone——团队新成员入项目一步到位。

## 变更与批量操作（首页）

- **变更文件树**：`仓库 → 目录 → 文件` 三层树展示工作区全部变更；节点可勾选，双击文件查看 Diff（未跟踪文件也能查看内容）;
- **三栏联动**：树单选 → 中栏提交图；点选提交 → 右栏该提交的 Diff；
- **批量操作**：勾选文件或仓库后，一次执行 `Add` / `回退` / `Pull` / `Fetch` / `Push` / `Commit`。所有批量操作走后台任务队列：实时进度、可取消、统一操作日志可回溯；
- **网络操作走系统 git**：兼容 Windows Credential Manager 与 SSH 配置，不需要在应用里再配一遍凭据。

## 完整 Git 客户端

| 功能 | 说明 |
| --- | --- |
| 分支管理 | 新建 / 重命名 / 删除 / 切换 / 比较 |
| Stash | push / pop / apply / drop，支持**工作区级 Stash**（跨仓库） |
| 交互式 Rebase | 拖拽排序提交，pick / reword / squash / drop，与冲突解决器联动 |
| Merge / 冲突解决器 | ours / theirs / 手动编辑，冲突感知视图 |
| Cherry-pick / Revert / Reset | 单提交级操作 |
| Reflog | 找回丢失的提交 |
| Worktree | 多工作树管理 |
| Diff 查看器 | 统一 / 分栏视图，Hunk/行级暂存，空白/大小写忽略选项 |
| 提交图 | SVG 泳道图，分支/标签标记，分页加载 |
| Change Set | 可命名、可勾选的工作区级变更集 |

## 批量与自动化

- **任务 DAG**：依赖感知编排，并行执行，部分失败语义；
- **工作区 Pipeline**：跨多仓库的编排工作流（构建、脚本动作、定时任务）;
- **文件变更监听**：工作区文件变化自动增量刷新状态；
- **Git 控制台**：fetch / pull / push 的 IDE 风格实时命令与输出。

## 提交热力图

Dashboard 提供 GitHub 风格的贡献热力图，聚合工作区内全部仓库的提交。
