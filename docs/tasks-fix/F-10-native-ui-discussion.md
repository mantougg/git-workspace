## 讨论议题

当前 UI 观感仍像「Web 套壳」，探讨让它更像原生客户端的方向。

## 候选方向（讨论素材，非任务）

- 窗口与系统融合：原生标题栏 / 自定义无边框标题栏（自定义需自绘窗口控制按钮与拖拽区）、系统主题跟随（亮/暗）
- 密度与字体：客户端级信息密度、等宽/系统字体栈、更小的默认字号与间距
- 交互习惯：右键上下文菜单、完整键盘快捷键体系、窗口尺寸/面板布局记忆
- 系统能力：托盘图标与常驻、系统通知、原生文件关联/拖放
- 视觉：减少「网页感」的大圆角/大留白，面板化布局（参照 IDE / Git 客户端）
- Tauri 层：窗口振动效果（vibrancy）、原生菜单

## 结论记录

2026-08-27 讨论结论：

1. **「原生感」的主战场是面板布局与皮肤密度，不是装饰性特性**。保留 Naive UI 与原生标题栏，不做无边框标题栏 / vibrancy / 托盘常驻。
2. **采用「Desktop Skin」三层方案而非自研组件库**：Design Tokens + Naive UI 全局 themeOverrides + 少量骨架组件（SideNav / StatusBar / Panel / Toolbar）。
3. **布局重构为 IDEA 式三段骨架**：左侧持久导航 + 内容区（视图即面板）+ 底部状态栏（收编 F-07 版本栏、TaskPanel 入口、watcher 状态、主题切换）。
4. **分三期实施**：一期布局骨架 → 二期视觉密度与亮暗主题 → 三期联动面板与右键/快捷键（可选，独立评估）。
5. 顺带发现需修复项：Dashboard 等视图残留 Element Plus 的 `--el-*` CSS 变量（项目使用 Naive UI，变量无效），在二期统一清理。

**完整改造方案：[../desktop-skin-plan.md](../desktop-skin-plan.md)**
