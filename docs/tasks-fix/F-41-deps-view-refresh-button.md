# F-41 Runtime 依赖页「刷新」按钮不好使（静默早退 + 视图不联动）

| 项 | 值 |
|---|---|
| 优先级 | P1 |
| 状态 | ✅ 已完成 |
| 来源 | 2026-09-04 用户反馈「依赖菜单的刷新按钮好像不是很好使」 |
| 关联任务 | F-15（workspaceId 派生修复）、F-17（工作区兜底先例）、R-20（树·图视图） |

## 问题描述

Runtime 依赖页（SideNav → 依赖）的「刷新」按钮点击后经常像没反应：

- 应用重启后从 SideNav 直达依赖页时，页面一直空白，点刷新才偶尔有数据；
- 已选中应用/项目时点刷新，树视图与项目详情仍是旧数据，看起来「没刷新」；
- 在 Dashboard 执行完「解析依赖」后回到依赖页，数据不会自动更新，必须手动点刷新。

## 根因（已定位）

`RuntimeDependenciesView.vue::reload` 存在三处缺陷：

1. **workspaceId 为空时静默 return**：`store.workspaceId` 派生自全局当前工作区
   （F-15），应用重启后直达本页时工作区列表可能仍在加载，`reload` 不转圈、
   不报错、无提示直接返回，且没有 watch 重试——页面永远空白。
2. **刷新后视图状态不联动**：`graph.value` 更新后，表格视图已选中项目的
   `inspection` 与树视图已构建的 `treeRoot` 仍持有旧图快照，用户看到的内容
   没有任何变化。
3. **解析完成无自动同步**：`dependency_resolved` 事件只在 store 层刷新
   projects/closureInfo，本页的本地 `graph` 不更新。

## 修复范围

- [x] `reload(manual = false)`：workspaceId 为空时先 `ensureWorkspace()`
      （加载工作区列表、自动选中首个），仍为空时手动点击给出
      「未选择工作区」提示，不再静默返回
- [x] 手动点击刷新成功后提示「依赖图已刷新」（挂载自动加载不打扰）
- [x] 刷新成功后联动：表格视图重取选中项目 inspection（项目已消失则清除选中），
      树视图按新图重建已选应用的依赖树
- [x] 视图内订阅 `dependency_resolved` 事件，「解析依赖」完成后自动重读依赖图

## 验收标准

- [x] 应用重启后直达依赖页，工作区就绪后自动加载依赖图，不再永久空白
- [x] 点击「刷新」有明确反馈（成功提示 / 错误提示 / 未选工作区提示）
- [x] 树视图选中应用时点刷新，依赖树按新图重建
- [x] Dashboard 执行「解析依赖」完成后，依赖页自动更新
- [x] `pnpm build`（vue-tsc + vite）通过
