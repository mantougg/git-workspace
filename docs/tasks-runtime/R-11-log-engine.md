## 目标

统一接管构建与应用进程的 stdout / stderr / application.log，提供实时滚动、过滤、搜索、导出的日志能力，并全程 Secret 脱敏。

## 需求范围

- [ ] 日志源接管（§35）：进程 stdout / stderr 实时捕获，落盘 `.gitworkspace/logs/`；支持读取应用自身 `application.log`
- [ ] 日志功能（§36）：实时滚动 / 暂停 / 清空 / 搜索 / 复制 / 导出 / 级别过滤（INFO / WARN / ERROR / DEBUG）
- [ ] 级别识别：主流日志格式（Logback / Log4j2 默认 pattern）的 level 解析，识别不出时降级为原文
- [ ] Secret 脱敏（§77）：`password=123456` → `password=******`；敏感环境变量值在日志中一并打码（全局约束 §4）
- [ ] 背压与资源控制：环形内存缓冲 + 批量聚合推送 UI；日志文件滚动切分与容量上限
- [ ] 为 §37 智能增强（Exception Detection / Stack Trace Folding / Error Highlight）预留解析接口位，本任务不实现

## 架构 / 性能注意点

- 日志洪水场景（Spring Boot 启动刷数千行）不得打爆 UI：发送端聚合节流，UI 侧虚拟滚动（前端渲染预算沿用全局约束）。
- 捕获线程与进程生命周期绑定，进程死即收；落盘写入用批量 flush，不逐行 sync。
- 脱敏在**落盘前**完成，保证磁盘上无明文 secret；脱敏规则与 T-08 共用。
- 大文件搜索/导出走流式读取，不整文件载入内存。

## 验收标准

- [ ] 应用启动日志实时可见，级别过滤/搜索/导出可用且导出内容与显示一致
- [ ] 高频输出下 UI 保持响应（事件聚合生效）
- [ ] 脱敏规则单测覆盖（含环境变量值、key=value 形态）
- [ ] 磁盘日志文件无未脱敏 secret（测试断言）
- [ ] 进程结束后日志完整保留、可回查
