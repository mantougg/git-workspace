# 00 全局开发约束（Runtime Workspace 横切关注点）

> 适用：**R-01 ~ R-26 全部任务**。
> 本文件记录「开发 Runtime Workspace 任何单个功能都必须遵守」的全局约束，与各任务文档里的「架构/性能注意点」**叠加生效**：
> - 任务文档只写该任务**特有**的注意点；
> - 这里写贯穿全文的**全局**约束。
>
> 本目录与 `docs/tasks/`（Git Workspace）同库共生：涉及 Git 联动（R-21）或改动共享基础设施（Scanner / SQLite / Task Queue / Watcher）时，`../tasks/00-全局开发约束.md` 一并生效。
> 开发任何单个功能前，先读本文件。
> 括注的 `§` 号指 `docs/大型企业项目轻量级开发运行工作台.md` 的章节号。

---

## 1. 三条产品边界（§3、§74、§92）

- **不替代 IDEA**：放弃代码编辑/补全/重构/索引，只做 Build + Runtime；不为 Runtime 功能引入 Java AST / 代码索引设施。
- **不重新实现 Maven / Gradle**：构建一律驱动外部 CLI（mvn / mvnw / mvnd / gradlew）；自研只做「发现、解析、映射、编排」，复杂解析（profile 激活、远程 resolve）交给构建工具自身。
- **Runtime Project 是可执行代码**：运行一个项目等价于执行其中的代码与构建脚本，所有执行路径必须可查、可控、可审计。

## 2. 用户项目只读原则（§17、§78）

- **绝不修改**用户的 `pom.xml`、源码、Git 分支等任何项目状态。
- 所有运行时生成物（Synthetic Reactor、缓存、日志、任务、索引）只写入 `.gitworkspace/`。
- `.gitworkspace/` 默认加入 `.gitignore`；其中 `runtimes/`、`environments/`、`templates/` 等用户配置类文件例外（设计目标就是可 Git 版本化、团队共享，§61），由用户选择是否提交。

## 3. 命令执行安全（§75）

- **禁止自动执行 shell script**（Pre/Post Build Script 等），除非用户显式允许；**第一次执行必须确认**。
- 进程启动命令（mvn / java / mvnw …）的完整参数必须可预览、可追溯到具体 Runtime 配置。
- 危险进程操作（Force Kill）需二次确认。

## 4. Secret 与环境变量安全（§76、§77）

- 敏感环境变量 key（`PASSWORD` / `TOKEN` / `SECRET` / `PRIVATE_KEY` / `API_KEY` 等）在 UI 一律掩码显示（`••••••••`）。
- **日志必须脱敏**：进程输出、应用日志、IPC 返回中出现的敏感值统一打码（`password=******`），脱敏规则单测覆盖。
- 与 T-08 的 Secret Protection 共用检测/脱敏能力，不另起一套规则。

## 5. 性能横切（§67 ~ §73、§99）

- 核心原则固定为 **Lazy / Incremental / Cache / Parallel / Batch**。
- 缓存三层：**POM Cache**（path + file hash → parsed model，pom 未变不解析）、**Dependency Graph Cache**（POM hash → graph / source mapping / closure）、**Runtime Build Cache**（第一阶段只用 Maven 原生 `~/.m2` 缓存，**不自行实现 Java 编译缓存**；缓存分级路线见 R-18）。
- 性能指标一律以 **R-08 Benchmark 实测为准**，不凭感觉；目标值（§99）：
  - Maven Project Discovery < 500ms
  - POM Cache Hit < 50ms
  - Dependency Graph Cache Hit < 100ms
  - Runtime Configuration Load < 50ms
  - Runtime UI 操作 < 50ms
  - File Change → Detection < 300ms
- Build 与 Spring Boot 启动时间**不设固定 SLA**，以项目规模与机器性能为基准记录趋势（§99）。

## 6. 并发调度（§66）

- **禁止所有 Maven 项目同时 Build**；构建/解析统一走 Runtime Task Scheduler 限流（起步：最大并发 Build = 2、Dependency Resolve = 4，可配置）。
- 调度复用 T-05 Task Queue / T-24 DAG，不新建并行执行框架。
- Maven/Java 子进程数计入系统预算；UI 全程保持响应，构建不阻塞 IPC。

## 7. 基础设施复用边界

| 能力 | 复用 | 禁止 |
|---|---|---|
| 仓库扫描 / workspace 清单 | T-01 Scanner | 另写一套目录遍历 |
| SQLite 数据层（WAL / 单写者 / 版本化迁移） | T-03 | 自建存储引擎 |
| 任务队列 / 进度 / 取消 | T-05、T-24 | 裸 spawn 无管理任务 |
| 文件监听（debounce / 分片 / 锁退避） | T-06 | 新建全局 watcher |
| Benchmark 设施 | T-07 | 另建性能采集 |
| 错误 / 日志 / Secret 脱敏 | T-08 | 另立错误体系 |

- Rust 模块落点遵循源文档 §51：`src-tauri/src/{runtime,maven,java,process}/`；前端落点 `src/{api,components,composables,stores,views}/`。
- IPC 类型单一事实来源沿用全局约束：Rust serde 结构 + golden-file 快照测试。

## 8. 配置分层（§61、§62）

- **SQLite 存元数据索引，`.gitworkspace/runtimes/*.json` 存用户配置**——Runtime 配置必须可 Git 版本化、可团队共享。
- 优先级固定为 **Application/Service → Runtime → Workspace → Global → System**（高层覆盖低层）。
- JSON 配置 schema 变更要向后兼容（缺省字段有默认值）。

## 9. 错误与日志（§79、§80）

- 错误分类固定使用 §79 集合：`ProjectNotFound / MavenNotFound / JdkNotFound / InvalidPom / DependencyResolveFailed / SourceMappingFailed / BuildFailed / ProcessStartFailed / PortOccupied / HealthCheckFailed / ProcessCrashed`，并携带结构化字段穿透 IPC 到 UI。
- **可行动错误提示**：不允许只显示 `Process exited with code 1`；必须给出 Reason + 上下文（PID / 端口 / 模块）+ Suggested Actions（§80）。
- 构建/运行日志分模块分流、可导出/清空，遵循第 4 节脱敏。

## 10. 网络边界

- 本地能力不依赖网络：项目发现、POM 解析、Source Mapping、Closure、Reactor 生成、进程管理、日志。
- 只有 Maven 自身解析远程依赖、拉取构件时才允许网络行为；GitWorkspace 侧**禁止**为「刷新状态 / 打开视图」发起任何远程仓库请求（Remote 依赖只标记，下载发生在 Build）。
- Maven 不可达远程仓库时，错误要可识别、可降级（提示检查网络 / settings.xml 镜像）。

## 11. 与 Git 联动的安全（§49）

- Runtime 运行期间执行 Checkout / 切分支等 Git 操作必须检测运行中应用并确认（`Stop & Switch / Cancel`）。
- Runtime 任何功能**不得主动修改 Git 状态**（commit / checkout / clean 等）。

## 与任务文档的配合方式

- 每个任务文档的「验收标准」里，性能项统一标注「以 R-08 Benchmark 实测为准」。
- 任务文档的「架构/性能注意点」只写该任务特有的坑；本文件的通用约束不再逐条重复。
- 若某任务与全局约束有冲突（例如临时放宽并发上限），必须在任务文档里显式说明原因与边界，否则默认遵守本文件。
