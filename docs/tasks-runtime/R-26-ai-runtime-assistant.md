## 目标

引入 AI 辅助 Runtime 排障：启动失败/运行异常的日志分析、错误解释与修复建议、配置优化建议——AI 只建议、解释、分析，不自动修改配置或代码。

## 需求范围

- [ ] 启动失败诊断：基于 Build/启动日志尾部 + 结构化错误（R-14 分类）给出原因解释与 Suggested Actions
- [ ] 运行异常分析：选中日志中的异常/堆栈，AI 解释成因与排查路径（呼应 §37 日志智能增强）
- [ ] 配置建议：根据项目特征（模块数 / Spring 版本 / JDK）建议 VM Options / Profile 等
- [ ] AI 请求安全（复用 T-08）：发送前 Secret 检测 + Preview + 可 Exclude 内容，日志摘要截断上限
- [ ] **AI as Assistant**：建议以可复制文本/一键应用确认形式呈现，任何落盘修改必须用户确认
- [ ] AI 不可用（未配置 Key / 离线）时 Runtime 核心功能完全不受影响

## 架构 / 性能注意点

- 日志入 prompt 前做摘要与截断（尾部优先），控制 token；大日志分块而非全量发送。
- 诊断结果与错误上下文一起展示，可追溯（哪次失败、用了哪些日志片段）。
- 请求异步化，不阻塞 Runtime 主链路；失败静默降级为普通错误提示。

## 验收标准

- [ ] 典型失败场景（端口占用 / 依赖缺失 / 配置错误）能给出有效诊断与建议
- [ ] AI 请求前 Secret 检测生效（测试断言）
- [ ] AI 未配置时全部入口优雅隐藏/降级
- [ ] 无任何自动修改行为（代码走查确认）
