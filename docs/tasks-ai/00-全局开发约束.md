# AI Assistant 全局开发约束

> 本文是 `docs/tasks-ai/` 全部 AI-XX 任务的**横切硬约束**，从 `docs/ai-assistant-design.md`（下称「设计文档」，§ 号指其章节）提炼。
> 任何 AI 任务开发前必读；各任务 spec 的「架构/性能注意点」只写该任务特有内容，与本文叠加，不重复。
> 涉及 Git/Runtime 联动时，`../tasks/00-全局开发约束.md`、`../tasks-runtime/00-全局开发约束.md` 与本仓库根 `AGENTS.md` 的平台兼容性规范一并生效。

## 1. AI as Assistant（设计文档 §2.2）

AI 只负责建议、解释、分析和生成。默认**不自动**：

- 修改用户源码、`pom.xml` 或其他项目文件；
- 修改 Git 分支、索引、提交、Push、Merge 或 Rebase 状态；
- 执行任意 shell、脚本或外部命令；
- 修改 Runtime 配置并落盘；
- 启动、停止、重启或 Kill 进程。

所有写操作必须经过「提案 → 预览 → 用户确认 → 现有命令/任务队列执行」。AI 层**不直接持有** `Repository` 句柄，也**不直接 spawn 子进程**（§10.3）。

## 2. 统一调用链（§2.2）

所有 AI 场景必须复用同一条链路，禁止在业务代码里另起 HTTP 调用：

```text
业务入口 → Context Builder → Secret 检测/脱敏/排除 → 发送 Preview（用户确认）
        → AI Gateway → Provider Adapter → 结构化结果 → 会话/缓存/审计/UI
```

- 发送前 Preview 未确认时，Gateway **不得访问网络**（§7.3）。
- 用户修改排除项后，必须重新计算 Secret 扫描、token 估算和内容 hash。

## 3. Offline First（§2.2 / §12.4）

- AI Provider 不可达不能影响状态刷新、Diff、Commit、构建、启动、日志、停止等本地能力；
- AI 未配置时入口隐藏或显示可行动的配置引导，不用浏览器原生 prompt 临时要 Key；
- 网络不可用时显示明确错误、保留用户 Preview 与输入上下文，**不能假装使用了本地模型**。

## 4. 凭证安全（§6.4，硬规则）

- API Key **只存 OS Credential Store**：Windows Credential Manager / macOS Keychain / Linux Secret Service；
- 凭证存储不可用时**不回退普通文件**，只允许本次会话临时输入（不落盘）；
- SQLite 只保存 `credentialRef` 与 Provider 元数据；
- Key 不得出现在：日志、错误信息、诊断导出、进程命令行、URL、Pinia 持久化、LocalStorage；
- 前端测试连接只返回成功/失败原因/模型能力，不回显响应敏感内容。

## 5. Secret 与 Preview（§10.1 / §10.2，硬要求）

- 复用 T-08 Secret Protection，**不另起规则**；策略：`Block`（默认阻断）/ `Mask` / `Exclude` / `Warn`（低置信度需用户明确确认）；
- Secret 检测发生在**最终内容生成之后**；脱敏后的内容仍需**二次扫描**；
- Preview 必须展示：Provider/模型、请求类型、目标范围、内容清单、每项字符数与估算 token、Secret 结果、脱敏项、排除项、预计请求次数、是否使用网络、明确的「确认发送」按钮；
- Preview 是硬要求，**不提供关闭开关**。

## 6. 上下文与隐私（§8 / §10.4）

- Context First：优先结构化摘要和必要片段，**不默认发送整个 Repository**；
- 上下文必须带 `contextManifest`：来源、范围、字符数、估算 token、是否脱敏/排除（§7.1）；
- 上下文构建器只调用现有领域服务，不直接扫描用户项目、不复制一份领域数据（§8.1）；
- 业务代码不得用字符串拼接把用户内容插入系统约束；用户日志/diff/文件内容作为不可信数据显式标记（§8.3）；
- 默认不保存完整 Prompt 敏感原文：只存 manifest、内容 hash、Secret 计数与类别、状态、token 用量、结构化结果（§10.4）。

## 7. 权限与工具（§9）

- 第一期工具**全部只读**；每个工具有：稳定名称与版本、JSON Schema 输入、角色白名单、上下文范围、超时与结果大小上限、审计字段；
- 一次用户请求的工具调用上限默认 **8 次**，达到上限返回「需要用户继续确认/缩小范围」；
- Agent 不得：自行扩大范围、后台持续观察、工具失败改用 shell、伪造工具结果、把一条指令拆成未展示的多个危险操作（§9.4）；
- 未来写工具只能返回 Action Proposal，真正执行仍走已有命令和任务系统。

## 8. 数据与存储（§11）

- 遵守 T-03 的 SQLite WAL、单写者、版本化迁移、向后兼容约束；
- `ai_reviews` / `ai_tasks` 历史数据保留或提供兼容读取，**不做破坏性删除**；
- 缓存 Key = `taskKind + modelId + promptVersion + contextHash + settingsHash`；**不得跨模型/跨 Provider 复用**；缓存结果带生成时间与 context hash，UI 不得把过期结果显示成当前事实；
- 删除会话须级联删除消息内容与相关本地缓存。

## 9. 错误模型（§17）

- 使用结构化 `AppError::Ai` 错误 code（`AiNotConfigured` / `AiCredentialUnavailable` / … / `AiActionConfirmationRequired`）；
- 每个错误携带：`message`（用户可读）、`details`（非敏感字段）、`recoverable`、`suggestedActions`；
- 模型能力不匹配、超出上下文限制等问题在**请求前**报错，不等 Provider 返回模糊失败（§6.3）。

## 10. 性能与异步（§16.1）

- AI 请求全异步，不阻塞 IPC、Runtime 状态机和日志采集；有**独立的请求并发上限**（不占 Maven/Java 子进程预算）；
- 大日志/大 diff 摘要、截断或分块；前端流式输出合帧，避免每 token 触发完整重渲染；
- 工具结果设数量与 payload 上限；会话列表分页、消息按需加载；
- 打开 AI 设置或 Assistant 页面不得触发全量 Repository 扫描。

## 11. 跨平台（§16.2 + 根 AGENTS.md 平台规范）

- Provider URL 用结构化 URL 处理，不手写字符串拼接；
- OS Credential Store 按 Windows / macOS / Linux 分支实现，环境不可用的测试 **skip 并打印原因**（不硬失败），但产品逻辑必须返回可行动错误；
- 网络和 TLS 错误归一化为统一错误，不依赖 shell 命令；
- API Key 不出现在进程命令行（三平台进程列表都会泄漏）。

## 12. 日志与审计（§16.3）

- 复用 T-08 的 `ai.log`：记录 requestId、taskKind、Provider/model ID、生命周期状态、耗时、重试次数、上下文 item 数、token 估算、脱敏计数、错误 code；
- **不记录** API Key、完整 Prompt、Secret 原文、未经用户同意的完整代码内容；
- 结果必须区分：AI 推断 / GitWorkspace 确定性事实 / 待用户确认的建议 / 已执行的实际动作（§8.4）。

## 13. 基础设施复用边界

| 能力 | 复用 | 禁止 |
|---|---|---|
| Secret 检测 / 日志 | T-08 | 另起扫描规则、另建日志通道 |
| SQLite / 迁移 | T-03 | 绕过单写者与版本化迁移 |
| Diff / Status / History | T-02 / T-04 等现有 Git 服务 | AI 层直接操作 git2 句柄 |
| Runtime 日志 / 错误 / 端口 | R-11 / R-14 / R-16 | AI 层重复实现错误分类、端口检测 |
| 任务执行 / Undo | T-05 / T-24 / T-34 | AI 直接执行写操作 |
| 命令与快捷键 | 命令注册表（desktop-skin 约定） | 视图内各自绑定快捷键 |

AI 层只**编排**，不重复实现 Runtime 或 Git 领域逻辑（§5.2）。代码落点：后端 `src-tauri/src/ai/` + `src-tauri/src/commands/ai.rs`（IPC 薄适配），前端 `src/{api,components/ai,composables,stores,types,views}/`。
