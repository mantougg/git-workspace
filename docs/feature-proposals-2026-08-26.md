# GitWorkspace 功能增强提案

> 文档日期：2026-08-26
> 基于项目现状分析，提出可增加或优化的功能方向

---

## 一、Git 功能增强

### 1.1 Blame 视图

**优先级：** ⭐⭐⭐⭐
**工作量：** 中

当前有 diff 查看器和 commit graph，但缺少 `git blame` 视图。

**功能描述：**
- 逐行展示文件的最后修改者和 commit
- 点击 blame 行跳转到对应 commit 详情
- 与 diff 查看器联动（blame 某个文件 → 查看该 commit 的完整变更）
- 支持忽略空白变更的 blame（`-w` 参数）

**技术要点：**
- 后端：`git2::Repository::blame()` 已有 libgit2 支持
- 前端：复用 `SideBySideDiff` 组件的布局，左侧增加 blame 信息列

---

### 1.2 Submodule 管理

**优先级：** ⭐⭐⭐
**工作量：** 中

多仓库场景下 submodule 使用频繁，目前没有相关支持。

**功能描述：**
- submodule 列表和状态展示（路径、URL、当前 commit、是否最新）
- 初始化/更新/同步操作
- 嵌套仓库的可视化（父子关系树）
- 批量 submodule 更新

**技术要点：**
- 后端：`git2::Repository::submodules()` 获取列表
- 需要处理 `.gitmodules` 文件解析
- submodule 状态需要递归检查

---

### 1.3 Git Hooks 管理

**优先级：** ⭐⭐⭐
**工作量：** 小

可视化管理 `.git/hooks/` 目录。

**功能描述：**
- 查看已安装的 hooks 列表和内容
- 启用/禁用单个 hook（重命名文件）
- 从模板创建常用 hook（pre-commit、commit-msg、pre-push）
- Hook 执行日志查看

**技术要点：**
- 纯文件操作，无需 git2 特殊支持
- 可以集成 husky/lint-staged 配置检测

---

### 1.4 Interactive Rebase UI

**优先级：** ⭐⭐⭐
**工作量：** 大

当前有 rebase 操作，但缺少交互式 rebase 的可视化界面。

**功能描述：**
- Commit 列表展示，支持拖拽排序
- 每个 commit 可选择操作：pick / squash / fixup / reword / drop / edit
- 编辑 commit message 的内联编辑器
- 预览 rebase 结果
- 冲突处理（复用现有 ConflictResolver）

**技术要点：**
- 后端：需要实现 `git rebase -i` 的等价逻辑（git2 rebase API）
- 前端：拖拽排序 + 操作选择 UI
- 复杂度较高，建议分阶段实现

---

### 1.5 Git LFS 支持

**优先级：** ⭐⭐
**工作量：** 中

大文件仓库的 LFS 状态展示。

**功能描述：**
- LFS 文件列表和大小展示
- LFS 追踪状态
- LFS pull/push 操作
- 存储用量统计

**技术要点：**
- 需要调用 `git lfs` 命令行（git2 不直接支持 LFS）
- 解析 `.gitattributes` 中的 LFS 规则

## 二、协作与集成

### 2.1 PR/MR 集成

**优先级：** ⭐⭐⭐
**工作量：** 大

打通本地-远程工作流。

**功能描述：**
- GitHub/GitLab PR 列表和状态展示
- 从当前分支创建 PR
- PR Review 状态和评论展示
- 合并 PR（merge/squash/rebase）
- PR 与本地分支的关联

**技术要点：**
- GitHub API / GitLab API 集成
- OAuth 认证流程
- 需要存储 API token（安全存储）

---

### 2.2 Remote 仓库管理

**优先级：** ⭐⭐⭐
**工作量：** 小

当前缺少 remote 管理界面。

**功能描述：**
- Remote 列表展示（名称、URL、fetch/push 分支映射）
- 添加/删除/修改 remote
- Fork 关系可视化（upstream/origin）
- Remote 分支列表和状态

**技术要点：**
- `git2::Repository::remotes()` 获取列表
- `git2::Repository::remote_set_url()` 修改 URL

---

### 2.3 团队工作区共享

**优先级：** ⭐⭐
**工作量：** 中

当前工作区配置是本地的。

**功能描述：**
- 工作区配置导出为可分享的模板
- 从团队模板创建工作区
- 工作区配置版本管理
- 与 Manifest 功能整合

**技术要点：**
- 复用现有 Manifest 导出/导入功能
- 可以支持 JSON/YAML 格式

## 三、开发者体验

### 3.1 命令面板（Command Palette）

**优先级：** ⭐⭐⭐⭐⭐
**工作量：** 中

类似 VS Code 的 `Ctrl+Shift+P`，是提升效率最显著的功能。

**功能描述：**
- 全局快捷键 `Ctrl+Shift+P`（macOS: `Cmd+Shift+P`）唤出
- 模糊搜索所有操作（Git 操作、页面导航、设置等）
- 最近使用的命令优先展示
- 支持参数输入（如：`checkout branch: feature/xxx`）
- 命令分类（Git / Navigation / Runtime / Settings）

**命令示例：**
```
> Fetch All
> Pull Current Branch
> Push to Origin
> Create Branch
> Open Diff Viewer
> Switch to Runtime Dashboard
> Toggle Dark Theme
> Refresh All Repositories
```

**技术要点：**
- 前端：Naive UI 的 `n-auto-complete` 或自定义组件
- 命令注册机制：各模块注册自己的命令
- 搜索算法：模糊匹配（fuse.js 或自实现）

---

### 3.2 快捷键系统

**优先级：** ⭐⭐⭐⭐
**工作量：** 中

当前没有全局快捷键支持。

**功能描述：**
- 可配置的快捷键映射（JSON 配置文件）
- 默认快捷键方案：
  - `Ctrl+R` — 刷新当前仓库状态
  - `Ctrl+Shift+P` — 命令面板
  - `Ctrl+1/2/3...` — 切换页面
  - `Ctrl+B` — 切换侧边栏
  - `Ctrl+Enter` — 确认对话框
- 快捷键冲突检测
- 快捷键提示（按钮 tooltip 中显示）

**技术要点：**
- `@vueuse/core` 的 `useMagicKeys` 或原生 `addEventListener`
- 快捷键配置持久化到本地存储

---

### 3.3 主题系统

**优先级：** ⭐⭐⭐⭐⭐
**工作量：** 小

桌面应用标配，用户期望高。

**功能描述：**
- 暗色/亮色主题切换
- 自定义主题色（主色调）
- 跟随系统主题（`prefers-color-scheme`）
- 主题持久化到本地存储

**技术要点：**
- Naive UI 原生支持主题切换（`darkTheme`）
- `useThemeVars()` 获取当前主题变量
- CSS 变量覆盖实现自定义主题色

---

### 3.4 通知系统

**优先级：** ⭐⭐⭐
**工作量：** 小

长时间操作完成后的通知。

**功能描述：**
- 系统通知（Tauri 原生支持 `tauri::api::notification`）
- 声音提醒（可选）
- 通知中心（历史通知列表，可查看/清除）
- 通知规则配置（哪些操作触发通知）

**技术要点：**
- Tauri 2 通知 API
- 前端通知状态管理

---

### 3.5 全局搜索

**优先级：** ⭐⭐⭐⭐
**工作量：** 中

跨仓库的搜索能力。

**功能描述：**
- 文件名搜索（跨所有仓库）
- 代码内容搜索（grep）
- Commit message 搜索
- 分支/tag 搜索
- 搜索结果高亮和上下文预览
- 搜索历史

**技术要点：**
- 后端：`walkdir` + 文件读取（或集成 ripgrep）
- 前端：搜索结果列表 + 预览面板
- 性能：后台搜索 + 结果流式返回

## 四、数据与分析

### 4.1 Git 统计面板

**优先级：** ⭐⭐⭐
**工作量：** 中

当前有健康检查，但缺少统计分析。

**功能描述：**
- 贡献者统计：
  - 每个贡献者的 commit 数量、lines added/removed
  - 贡献者排名
- 时间线分析：
  - 活跃度热力图（类似 GitHub contribution graph）
  - 按周/月的 commit 趋势
- 仓库大小趋势
- 分支生命周期分析（存活时间、合并速度）

**技术要点：**
- `git2::Revwalk` 遍历 commit 历史
- 统计数据缓存（避免重复计算）
- 图表组件（echarts 或自实现轻量图表）

---

### 4.2 工作区快照增强

**优先级：** ⭐⭐
**工作量：** 中

当前有 Workspace Stash，可以扩展。

**功能描述：**
- 定时自动快照（可配置间隔）
- 快照对比（两个时间点的差异）
- 回滚到某个快照
- 快照标签和备注

**技术要点：**
- 复用现有 Workspace Stash 机制
- 定时器管理

---

### 4.3 操作历史增强

**优先级：** ⭐⭐
**工作量：** 小

当前有 Operation Log，可以增强。

**功能描述：**
- 操作耗时统计（平均、最大、最小）
- 失败操作的重试建议
- 操作模式分析（"你经常在周五批量推送"）
- 操作成功率趋势

**技术要点：**
- 复用现有 Operation Log 数据
- 统计计算

## 五、Runtime 增强

## 六、性能优化

### 6.1 增量状态更新

**优先级：** ⭐⭐⭐⭐
**工作量：** 大

当前 `refreshStatus` 是全量扫描。

**功能描述：**
- 基于文件系统事件（`notify` crate）的增量更新
- 只刷新变更的仓库（而非全量扫描）
- 状态缓存的智能失效（只失效变更文件相关的缓存）
- 后台静默刷新（用户无感知）

**技术要点：**
- 已有 `FileWatcher` 模块，需要增强为增量更新
- 文件变更 → 仓库状态 diff → 局部缓存更新
- 需要处理文件系统事件的去重和合并

---

### 6.2 大仓库优化

**优先级：** ⭐⭐⭐
**工作量：** 中

对于超大仓库（1000+ 文件）。

**功能描述：**
- 虚拟滚动扩展应用范围（已有 VirtualList 组件）
- 分页加载 commit history（当前可能一次性加载全部）
- 按需加载 diff（只在选中时计算）
- 搜索结果分页

**技术要点：**
- 复用现有 `VirtualList` 组件
- 后端分页 API（offset/limit）

---

### 6.3 后台索引

**优先级：** ⭐⭐
**工作量：** 中

启动时的仓库扫描优化。

**功能描述：**
- 后台渐进式索引（不阻塞 UI）
- 优先展示已索引的仓库
- 索引进度指示器
- 增量索引（只扫描变更的目录）

**技术要点：**
- 异步索引任务
- 进度事件通知前端

## 七、推荐实施路线

### 第一阶段：开发者体验（1-2 周）

| 功能 | 优先级 | 工作量 | 价值 |

| 暗色主题 | ⭐⭐⭐⭐⭐ | 小 | 高 |

**理由：** 这三个功能对用户体验提升最大，且实现成本相对可控。暗色主题是桌面应用标配，命令面板和快捷键是效率工具的核心。

### 第二阶段：Git 功能补全（2-3 周）

| 功能 | 优先级 | 工作量 | 价值 |
|------|--------|--------|------|
| Blame 视图 | ⭐⭐⭐⭐ | 中 | 高 |
| Remote 管理 | ⭐⭐⭐ | 小 | 中 |
| 全局搜索 | ⭐⭐⭐⭐ | 中 | 高 |

**理由：** Blame 和全局搜索是 Git 工具的核心功能，Remote 管理是基础功能补全。

### 第三阶段：协作与分析（3-4 周）

| 功能 | 优先级 | 工作量 | 价值 |
|------|--------|--------|------|

| 通知系统 | ⭐⭐⭐ | 小 | 中 |

**理由：** PR 集成打通本地-远程工作流，统计面板提供数据洞察，通知系统提升体验。

### 第四阶段：高级功能（按需）

| 功能 | 优先级 | 工作量 | 价值 |
|------|--------|--------|------|
| Interactive Rebase | ⭐⭐⭐ | 大 | 中 |
| Docker 支持 | ⭐⭐⭐ | 大 | 中 |
| Submodule 管理 | ⭐⭐⭐ | 中 | 中 |

## 八、技术债务清理建议

在开发新功能的同时，建议同步处理以下技术债务：

| 项目 | 优先级 | 说明 |
|------|--------|------|
| Runtime `lock().unwrap()` 改造 | P0 | 防止级联 panic |
| Router 404 路由和守卫 | P0 | 防止空白页 |
| RepositoryList.vue 拆分 | P1 | 2193 行巨型组件 |
| Store 错误处理统一 | P1 | 静默失败 → 状态字段或传播 |
| 全局错误边界 | P2 | 防止白屏 |

---

## 九、总结

GitWorkspace 已经是一个功能丰富的多仓库 Git 管理工具。在继续扩展功能的同时，建议：

1. **优先提升开发者体验** — 命令面板、暗色主题、快捷键是效率工具的标配
2. **补全 Git 核心功能** — Blame 视图、全局搜索、Remote 管理
3. **打通协作流程** — PR 集成是本地-远程工作流的关键节点
4. **同步清理技术债务** — 特别是 Runtime 模块的 unwrap 风险

功能开发与技术债务清理可以并行推进，避免债务累积影响后续开发效率。
