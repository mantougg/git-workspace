# GitWorkspace Runtime Workspace
# 产品需求与技术架构设计文档

> 文档版本：V1.0
> 模块名称：Runtime Workspace
> 所属产品：GitWorkspace
> 产品定位：轻量级 Java / Spring Boot 项目运行工作区
> 技术基线：Rust + Tauri 2 + Vue 3 + TypeScript + SQLite
> 首要目标：在不启动 IDEA / IntelliJ IDEA 的情况下，实现大型多仓库 Maven / Spring Boot 项目的快速构建、运行、停止、重启和日志管理。

---

# 1. 背景

## 1.1 现状

大型企业 Java 项目通常由大量 Git Repository 组成：

```text
workspace/
├── common/
├── core/
├── auth/
├── system/
├── workflow/
├── gateway/
├── web/
└── boot/
````

实际开发过程中，经常存在以下角色：

* 开发人员：需要完整代码编辑、代码补全、调试、重构能力；
* 测试人员：主要需要启动、停止、查看日志、切换环境；
* 产品人员：可能只需要启动项目进行功能演示；
* 运维人员：需要启动、停止和观察服务；
* 联调人员：需要启动多个服务；
* CI / 自动化人员：需要快速构建并启动项目；
* AI Agent：需要构建和运行项目，但不需要 IDE。

对于后几类用户，完整启动 IDEA 存在明显的资源浪费。

# 2. 问题定义

传统方式：

```text
打开 IDEA
    ↓
加载整个项目
    ↓
扫描大量源码
    ↓
建立 Java Index
    ↓
加载 Maven Project
    ↓
建立 IDE 内部模型
    ↓
启动 Spring Boot
```

其中真正运行 Spring Boot 所必需的部分实际上只有：

```text
Maven Project Model
+
Dependency Resolution
+
Compilation
+
JDK
+
Spring Boot JVM
```

而以下能力并不是运行项目必须的：

```text
Java Code Index
Code Completion
Refactoring
AST Analysis
IDE Project Model
IDE Plugins
Editor
Code Navigation
```

因此 GitWorkspace 应提供：

```text
GitWorkspace
    ↓
Maven Project Discovery
    ↓
Dependency Graph
    ↓
Local Source Mapping
    ↓
Required Module Closure
    ↓
Build
    ↓
Spring Boot Run
```

# 3. 产品定位

Runtime Workspace 不是 IDEA 的替代品。

它的定位是：

> 一个面向大型多仓库 Java 项目的轻量级 Build & Runtime Workspace。

核心原则：

```text
IDEA
=
Code Intelligence
+
Build
+
Runtime

GitWorkspace Runtime
=
Build
+
Runtime
```

Runtime Workspace 主动放弃：

```text
代码编辑
代码补全
代码重构
代码索引
IDE Project Model
```

只保留：

```text
项目发现
依赖分析
源码映射
Maven / Gradle 构建
JDK 管理
Spring Boot 启动
进程管理
日志管理
运行环境管理
多服务编排
```

# 4. 产品目标

## 4.1 核心目标

实现：

```text
打开 Workspace
    ↓
自动发现 Maven 项目
    ↓
选择 Spring Boot 项目
    ↓
自动分析 Maven 依赖
    ↓
自动发现 Workspace 中的源码依赖
    ↓
建立 Runtime Dependency Closure
    ↓
只构建必要模块
    ↓
启动 Spring Boot
```

---

## 4.2 资源目标

目标不是保证 Spring Boot 本身占用很少内存，而是：

> 最大限度消除 IDE 层面的资源开销。

目标架构：

```text
传统：

IDEA
├── IDEA JVM
├── Java Index
├── Maven
├── File Watcher
├── Plugins
└── Spring Boot JVM


Runtime Workspace：

GitWorkspace
├── Rust/Tauri
├── Maven
└── Spring Boot JVM
```

最终应通过 Benchmark 验证：

```text
IDEA + Spring Boot
vs
GitWorkspace Runtime + Spring Boot
```

比较：

* 启动时间
* 空闲内存
* 峰值内存
* CPU
* 磁盘 IO
* 文件句柄
* JVM 数量
* 后台进程数量

# 16. Runtime Reactor

对于标准 Maven 多模块项目：

```text
直接复用 Maven Reactor
```

对于跨 Repository：

```text
自动生成 Synthetic Runtime Reactor
```

例如：

```text
.gitworkspace/
└── runtime/
    └── boot/
        └── pom.xml
```

生成：

```xml
<packaging>pom</packaging>

<modules>
    <module>../../repo-common/common</module>
    <module>../../repo-core/core</module>
    <module>../../repo-auth/auth</module>
    <module>../../repo-boot/boot</module>
</modules>
```

---

# 17. Synthetic Reactor 原则

必须：

```text
不修改用户原始 pom.xml
```

所有运行时生成文件放在：

```text
.gitworkspace/
```

例如：

```text
.gitworkspace/
├── runtime/
├── cache/
├── logs/
├── tasks/
└── index/
```

并默认加入：

```text
.gitignore
```

# 29. Start 流程

推荐不要强制使用：

```text
mvn spring-boot:run
```

作为唯一实现。

应该抽象：

```text
Build Engine
       ↓
Artifact / Classpath
       ↓
Runtime Launcher
       ↓
java
```

例如：

```text
mvn -pl boot -am package
```

之后：

```text
java
  -cp ...
  com.example.Application
```

这样 GitWorkspace 可以更加精确地控制：

```text
JVM
Classpath
Environment
Arguments
PID
Process
```

同时也更容易实现：

```text
Restart
Monitoring
Debug
```

# 30. Spring Boot Run Strategy


```text

```

```text
Classpath Run

```


具体默认策略应通过 Benchmark 决定。

```text
跨 Repository Maven 源码映射
+
Runtime Dependency Closure
+
Synthetic Reactor
+
最小构建范围

JDK / Maven 自动管理
+
多服务编排
+
进程管理
+
日志管理

与 Git Workspace 联动
```

```text
        ↓

        ↓

        ↓

        ↓

        ↓

        ↓
启动
```
