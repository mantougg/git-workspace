# 00 全局开发约束（Node 前端工程启动 · 横切关注点）

> 适用：**N-01 ~ N-09 全部任务**。
> 本文件只写 Node 扩展**特有**的横切约束。以下两份约束**全文生效、不重复**：
> - `../tasks-runtime/00-全局开发约束.md`（Runtime 引擎全局约束：三条产品边界 / 用户项目只读 / 命令执行安全 / Secret / 性能 / 并发调度 / 基础设施复用 / 配置分层 / 错误日志 / 网络边界 / Git 联动安全）
> - 根 `AGENTS.md`「平台兼容性开发规范」（路径归一化 / 可执行检测 / 进程 / 测试断言）
>
> 冲突时以 Runtime 全局约束为准，并在任务 spec 显式说明原因与边界。

---

## 1. 不实现 npm script 语义（设计文档 §3 核心原则）

- Node 路径只做「检测可执行 + 拼命令 + 复用进程管理」；script 内容交给包管理器自身执行，**不解读、不改写、不静态分析** `scripts` 的命令文本。
- 对齐 Runtime 全局约束 §1「不重新实现 Maven / Gradle」：不重新实现 npm/pnpm/yarn 的任何解析能力。

## 2. 网络边界：禁止自动 `npm install`

- 依赖安装是网络行为，**任何启动链路不得隐式触发 install**（Runtime 全局约束 §10）。
- 仅 N-08 提供显式 `node_install` IPC：用户主动触发 + 任务进度可见 + 首次确认（对齐 §75 脚本确认制）。
- 启动前检测 `node_modules` 缺失：给可行动提示（Suggested Action = 执行 install），不代劳。

## 3. 可执行文件检测（Windows 硬规则）

- node / npm / pnpm / yarn 检测**一律走** `java/detect.rs::find_in_path`（`.exe → .cmd → .bat → 裸名`）；Windows 上包管理器实体是 `.cmd` shim，直接 `Command::new("npm")` 会命中不可执行的 Unix shim（os error 193）。
- 执行 `.cmd/.bat` 必须经 `cmd /C`（`maven/detect_exec.rs::needs_cmd_c`）；Unix 直接 spawn。
- 版本探测仿 `probe_version`：超时 + 输出上限，失败降级为「未知版本」而非报错。

## 4. 错误分类扩展（对 §79 的显式增补）

- 本套任务新增三个错误码：`NodeNotFound` / `PackageManagerNotFound` / `ScriptNotFound`（设计文档 §4.7）。这是对 Runtime 全局约束 §9 固定集合的**显式扩展**，在引入它们的 spec（N-01 / N-03）中已声明。
- 新增错误必须携带结构化字段穿透 IPC 到 UI，且附 Suggested Actions（§80 可行动错误），不允许裸退出码。

## 5. 检测器与解析保持纯函数

- banner/端口检测器、包管理器决策链、`--port`/`PORT` 解析、package.json 解析：**输入输出样例可单测的纯函数**，系统调用只留一个入口（对齐 `process/port.rs` 的既有模式）。
- 检测器样例必须取自真实工具输出（Vite / webpack / Next 原文），不凭记忆编造。

## 6. 测试环境策略

- 依赖 node/npm 的测试：**探测不到就 skip 并打印原因**（根 AGENTS.md §4），不硬失败；产品逻辑（如 `NodeNotFound`）必须返回可行动错误。
- fixture 目录用 `std::env::temp_dir()`；断言含路径先 `replace('\\', "/")` 归一化。
- schema 迁移测试：旧版本库升级幂等（沿用 `db/schema.rs` 既有测试模式）。
