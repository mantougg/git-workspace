# 后端模块拆分 全局开发约束

> 本文是 `docs/tasks-backend/` 全部 B-XX 任务的**横切硬约束**，从 `docs/backend-module-split-plan.md`（下称「设计文档」，§ 号指其章节）提炼。
> 任何 B-XX 任务开发前必读；各任务 spec 的「架构/性能注意点」只写该任务特有内容，与本文叠加，不重复。
> 根 `AGENTS.md` 平台兼容性规范与本仓库 GitNexus 规则（impact / detect_changes）一并生效。

## 1. 不变式（设计文档 §1 / §11，最高优先级）

拆分前后必须保持不变：

- **IPC 契约**：命令签名、serde 字段、golden 快照不因为拆分而变化；
- **事件名与 payload**：Tauri 事件名称和负载结构不变；
- **数据库 schema 与用户配置格式**：不新增/修改表结构，不改 `.gitworkspace/runtimes/*.json` 格式；
- **任务语义**：Build/Start/Stop/Restart 等仍通过 TaskManager 执行，任务类型分发不变；
- **跨平台行为**：Windows/macOS/Linux 的进程、路径、命令行为不变；
- **公共路径兼容**（§5.3）：`runtime::RuntimeService`、`runtime::RuntimeProcessManager`、`runtime::RuntimeOperationRequest`、`maven::sync_workspace_index`、`maven::query_dependency_graph`、`maven::DependencyGraphCache`、`runtime::logs::RuntimeLogEngine` 等经 `mod.rs` re-export 保持可用。

发现必须改变以上任何一项才能完成拆分时：**停下来**，在设计文档中补充说明并确认后再动。

## 2. 迁移方式（§5）

- 文件改目录：`xxx.rs` → `xxx/mod.rs`，**不得**同时保留同名 `.rs` 与目录（§5.1）；
- `mod.rs` 只保留公共类型、共享状态、构造函数和必要的 `pub use`（§1）；
- 访问权限（§5.2）：对外用 `pub`；子模块间共享用 `pub(super)`；**不为方便拆分把字段改成 `pub`**；不用 `pub(crate)` 扩大领域内部暴露；
- 查询、写操作、后台 worker、平台适配、测试不混在同一个实现文件（§1）；
- 测试外移用同父模块 `tests.rs`（`#[cfg(test)] mod tests;`），继续访问私有成员，**不为测试扩大生产可见性**（§5.4 / §10.5）。

## 3. 小步验证（§9）

- 每一步只移动**一个职责组**，移动后立即执行四件套：

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

- 迁移顺序：**接口/公共类型 → 实现 → 调用方 → 测试**（§9）；
- 环境相关测试（Maven/JDK/网络）缺失时按项目规则 skip 并打印原因，产品逻辑错误不得用 skip 掩盖；
- 每阶段结束检查 Git diff：只允许预期文件和符号变化；
- **回滚粒度 = 一个职责组**（§9），不做整个后端大回滚。

## 4. GitNexus 流程（§9 + 根 AGENTS.md）

- 移动任何公共符号前：先跑 `impact({target, direction: "upstream"})` 确认直接调用方与执行流，向用户报告 blast radius；HIGH/CRITICAL 风险必须提示后再继续；
- 禁止 find-and-replace 改名，用 GitNexus `rename`；
- 提交前跑 `detect_changes()`，确认影响范围不超出预期；
- 用源码搜索兜底字符串形式的引用：命令名、事件名、配置字段、模块路径。

## 5. 数据库与并发（§7）

- 生产代码继续共享 `Arc<Mutex<rusqlite::Connection>>`，保持现有 WAL / busy timeout / 事务策略，拆分**不**顺手改并发模型；
- Maven/Java 长进程执行期间不得持有 DB 锁；进程/任务状态与索引同步的写操作保持短事务；
- 缓存失效由同步用例统一负责，查询服务不直接改缓存失效状态；
- Maven 索引同步保持原子性：失败不留半套索引，`graph_cache` / `closure_cache` 失效时机不变（§4.4）。

## 6. 跨平台（§8 + 根 AGENTS.md）

- 路径比较两侧归一化（`replace('\\', "/")`），禁止裸 `==`；Windows verbatim 前缀（`\\?\`）经统一清理；
- 平台分支集中在 `process/`、`launcher.rs` 或专门 adapter——**拆分时不得把平台分支散落到多个业务模块**（§8）；
- 进程树终止走 `process/kill_tree.rs`；子进程输出监控遵守 F-12（reader 断开后不阻塞 `child.wait()`、按字节读 + `from_utf8_lossy`）；
- 超长 classpath 继续走 pathing jar；Windows 可执行检测走 `find_in_path`；`.cmd`/`.bat` 经 `cmd /C`；
- 含临时目录的测试用 `std::env::temp_dir()`；`#[cfg(windows)]` 编译期分支保留。

## 7. 克制项（§10，明确不做）

- 不按行数硬切（§10.1）；
- 不拆多 crate（§10.2）；
- 不立即全面 Hexagonal / 不为每个 DAO、DTO、路径工具加 trait（§10.3，Port/Adapter 只走 B-10 的触发条件）；
- 不建包揽所有表的大 Repository / `DatabaseService`（§10.4）；
- 不把测试全部改成 integration test（§10.5）；
- 不顺手做与拆分无关的重构、改名、格式化——diff 保持可审查。

## 8. 文档同步（§9 第 6 条）

任务完成时，若被根 `AGENTS.md` 平台规范「参照实现」或其他文档引用的符号路径发生变化（如 `runtime/service.rs` → `runtime/service/queries.rs`），必须同任务内更新这些文档引用，不留死链。
